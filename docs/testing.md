# Portable tests and scientific reproduction

## Clean checkout

Requirements: a supported Node.js release for the pinned dependencies (Node 24 is the validated version), npm, and **Python 3.10+** for standard-library-only scientific generators. Install dependencies in `engine/`, then use the repository's package scripts:

```sh
cd engine
npm ci
npm test
npm run typecheck
npm run build
```

Use a **clean checkout or isolated export**, not a deployment directory. The pre-build guard `scripts/check-build-output.mjs` refuses a symlink at `engine/dist` **before** TypeScript or Vite can emit files. It makes no changes, does not remove the symlink, and is not a deployment/rollback command. An absent or ordinary directory output in an isolated checkout is accepted. Do not bypass the guard with a direct Vite/TypeScript emit command on a live deployment checkout.

The Node test suite uses bounded concurrency/timeouts. It needs only installed dependencies, committed `engine/src`, `engine/public`, `engine/tests`, `engine/scripts` and the root `test-data/` directory. It does **not** require a historical release, deployment backup, private evidence directory, network API, browser installation or native graphics driver. Vite dev-route tests start and close their own local test server. Mock DOM/GL tests establish scheduling, geometry and wiring, **not browser paint, real-device input, GPU pixels or hardware FPS**.

## Scientific inputs and licenses

See [`../test-data/README.md`](../test-data/README.md) for exact source versions, licenses/qualified fact-use rationale, curation disclosures and original hashes. The source data are **not all MIT**. In particular HYG data/adaptations are CC BY-SA 4.0, and no blanket JPL redistribution license is asserted.

HYG v4.1 is retained as one deterministic gzip, with the complete original CSV bytes inside. No automatic download or extraction is performed by `npm test`. Horizons reference tables retain the exact scientific table blocks, minus private capture wrappers and nonessential footer prose; original and curated hashes are both disclosed. No numerical acceptance threshold was loosened for portability.

## Read-only regeneration checks

All paths are resolved from the script location, not a particular host or current working directory:

```sh
cd engine
python3 scripts/spacecatalog/generate.py --check
python3 scripts/stellar/generate.py --check
python3 scripts/generate-lod.py --check
node --import tsx scripts/stellar/verify.ts --check
```

- Spatial catalog: all **9,078** selected HYG rows, coordinate conversions, catalog and credit bytes.
- Stellar metadata: exact source cross-identifiers/spectral strings, literature anchors, metadata and credit bytes; compare the immutable generation summary.
- Legacy observer LOD0–4: **520 / 2,313 / 12,625 / 67,665 / 32,394** stars, reproducing the existing little-endian binaries from the same pinned CSV. The older script's literal escaped-newline syntax and unpinned network fallback were removed. **LOD5–7 and `stars.bin` are not regenerated by this script.**
- Model verifier: current numerical/model coverage plus retained asset/source hashes; it does not claim to have run the full test suite or TypeScript compiler.

`--check` never rewrites committed fixtures, public assets, generation dates or reports. The portability tests compare hashes before and after checks. Running a generator **without** `--check` intentionally regenerates its documented assets, so do that only in a working checkout, review the diff, and rerun checks.

Optional `--report` on the spatial/stellar generators (without `--check`) and on `scripts/stellar/verify.ts` writes reports beneath ignored `engine/test-results/`. Optional explicit `--download` on the spatial generator can restore a missing pinned source into that ignored cache; it validates the pinned decompressed SHA-256 and never replaces a committed fixture. It cannot be combined with `--check`; normal tests never invoke it.

## Historical negative controls

[`../engine/tests/fixtures/historical/README.md`](../engine/tests/fixtures/historical/README.md) explains the minimal exact old app and shader snapshots and their SHA-256 provenance. The old app's actual label algorithm is executed with current imports resolved by the test harness; it is **not** replaced by a fabricated failure/return value. The old stellar shader text remains an actual previous implementation. Tests keep the former negative-control assertions. These bounded controls are not a reconstruction or certificate for an entire historical release.

The original stellar-model preservation map also checks an exact archived catalog-generator snapshot; current generator output is independently byte-checked. Changing the portable I/O wrapper is not represented as preserving the current script's old source hash.

## Optional legacy packaged-observer smoke test

`tests/package-smoke.mjs` is **not** part of `npm test` and is not the build process for the current spatial app. If you deliberately produce a compatible historical single-file observer artifact, pass its location explicitly:

```sh
node tests/package-smoke.mjs /path/to/Galaxy-Observer-Preview.html
```

It checks the packaged observer against a mocked DOM/GL and writes only `engine/test-results/package-smoke/package-dom-smoke.json`. No `artifacts/` or private `evidence/` tree is assumed to exist. This optional legacy check has not been promoted into a browser or current-spatial-package acceptance test.
